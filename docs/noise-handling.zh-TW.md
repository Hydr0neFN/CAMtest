# 雜訊處理 — 試過哪些做法

戶外偵測亮點，誤判多到整個畫面都是。所以管線在一條路上依序疊了好幾道濾波器；亮點要全部通過，才會被回報成真實目標。

1. **亮度閾值**（`detector.cpp`）—— 只算像素值 ≥ 200/255 的像素，暗的背景直接濾掉。
2. **尺寸過濾** —— 小於 16 px 當雜訊；大於 70000 px 是整畫面過曝。兩種都丟掉。
3. **8-相連 CCL + 合併** —— 連通元件標記把亮像素分群，質心相距 30 px 以內的就合併（不然手機手電筒的兩顆 LED 晶粒會被當成兩個目標）。
4. **感測器邊緣剔除** —— 位於最前／最後幾行（`cy < 3` 或 `cy > height-4`）的亮點捨棄；`vflip`/`hmirror` 會讓這些邊緣出現亮線假影。
5. **自身車燈反光過濾**（`tracker_classify`）—— 畫面底部四分之一出現的大亮點，幾乎一定是自己的車燈打到路面。幾何很明確，所以不投票，直接強制歸類為 `STATIC_LIGHT`。
6. **訊框間遲滯** —— 亮點用最近質心和前一訊框配對，而且同一個類別要連續 **3 個訊框**（`TRACKER_CONFIRM_FRAMES`）一致才採信。單一訊框的閃爍永遠確認不了。
7. **跨相機 X/Y 比對 — 主要防線**（`main.cpp`，primary 迴圈）。primary 的亮點只有在 secondary 也有對應亮點、且符合下面兩個條件時才收：
   - **正向 X 視差** —— 左側（secondary）看到的亮點要比右側（primary）*更偏右*（`dx ≥ STEREO_MIN_DISPARITY`）。前方真有物體時，幾何上一定是這樣。
   - **2D 位置接近** —— 曼哈頓距離 `dx + |dy|` 小於約 200 px，代表兩邊看的是同一個東西。

   只有一邊看得到的、或視差正負號相反的亮點，一律剔除。光是這一道就能擋掉大部分單眼看到的反光。
8. **三角測距合理範圍**（`triangulation.cpp`）—— 算出的距離要在 0.5–80 m 內，視差要 ≥ 1 px，不然這組匹配作廢。
9. **全黑重設** —— 畫面沒有亮點時追蹤器清掉狀態，離開畫面的燈光留下的舊質心才不會之後配錯。

**還是有漏網的。** 跨相機 X/Y 比對是最強的一層，但還是有假目標撐得過去：兩台相機真的同時看到同一個假亮點時（濕路面反光、路標、第二個光源），正視差*和*位置接近都符合，於是被三角測距當成真目標。不管怎麼調單一線索的濾波，都分不出「騎士的車燈」和「兩台相機都看得到的其他亮東西」，這也就是專案擱置的關鍵。
